云端商店：支付宝自动发货部署

已内置 Worker 后端接口：

  • GET /api/products：商品列表
  • POST /api/create-checkout-session：创建支付宝收银台支付链接
  • POST /api/alipay/notify：支付宝异步回调监听（自动发货触发点）
  • GET /api/delivery?session_id=...：支付成功后读取发货内容

1. 配置支付宝密钥（必填）

在项目根目录执行：

说明：

  • ALIPAY_PRIVATE_KEY 需使用 PKCS8 PEM 格式（BEGIN PRIVATE KEY）
  • ALIPAY_PUBLIC_KEY 使用支付宝开放平台公钥（BEGIN PUBLIC KEY）

2. 开启持久化存储（推荐）

若不绑定 KV，订单会使用内存临时存储，实例重启后历史订单可能丢失。

创建 KV 后，在 wrangler.jsonc 取消注释 kv_namespaces 并填入真实 ID。

这样商品配置、库存与卡密池都写入 KV，后续 git push 只更新代码，不会覆盖线上运行数据。

2.1 管理接口（防推送覆盖）

  • GET /api/admin/products：读取当前线上商品配置（含库存）
  • POST /api/admin/products：写入线上商品配置
  • GET /api/admin/code-pool?productId=xxx：读取某商品卡密池
  • POST /api/admin/code-pool：覆盖或追加某商品卡密池
  • GET /api/admin/order?orderNo=...：按订单号查询订单详情（管理员）

鉴权方式（二选一）：

  • 请求头：x-admin-token: 你的 ADMIN_API_TOKEN
  • 或 Authorization: Bearer 你的 ADMIN_API_TOKEN

2.4 发货幂等说明（防重复发货）

  • 每个订单支付成功后会生成一次发货快照并持久化。
  • 同一订单重复访问发货接口时，会返回同一份发货内容，不会重新弹出新卡密。
  • GET /api/delivery 现在支持 session_id 或 order_no 查询。
  • 下单响应会返回 orderNo（示例：ORD-20260407-123456），可用于售后检索。

3. 部署 Worker

部署后将支付宝应用的 notify_url 配置为：

https://你的-worker-域名/api/alipay/notify

4. 联调建议

  1. 在支付宝沙箱环境先跑通下单与回调。
  2. 支付后访问 shop/success/?session_id=订单号，确认自动发货展示。
  3. 若未及时回调，前端会在读取发货时触发一次主动查单兜底。

5. 快速演示模式（可选）

将 wrangler.jsonc 中 ALIPAY_MOCK_MODE 设为 1，即可跳过真实支付，直接模拟支付成功并发货。
